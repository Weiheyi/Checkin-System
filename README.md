# 学习打卡系统

一个纯静态的学习打卡网站：每天打卡、记录任务、统计连续天数与完成率。
托管在 **GitHub Pages**，账号与数据由 **Supabase** 提供。

线上地址：https://Weiheyi.github.io/Checkin-System/

友情链接：[浣秋の語](https://www.leoworld.top/) —— 浣秋和同学的小站，AP 学习笔记 / 古诗词整理 / 技术折腾 / 影视推荐。

## 功能

- 邮箱 + 密码注册登录（不依赖任何邮件流程，注册后直接可用）
- 人机验证：登录、注册均需先通过「四则运算」快速验证
- 每日打卡（每人每天一次，重复打卡会被拦截）；**当天学习累计满 5 个不同单词会自动打卡**（背诵、考核都算）
- 任务管理：添加、勾选完成 / 取消、删除；**背完 / 考完一轮会按已完成为你自动记一条任务**
- 学习统计：连续天数、打卡天数、完成任务数、完成率
- 打卡历史：最近记录与完成进度
- 好友：邮箱精确添加 / 删除、好友打卡动态流、排行榜 PK、点赞鼓励、**私信聊天**、**动态评论**
- 学习论坛：**全站登录用户**都能发帖与评论；发帖**必带标题**、正文可选，帖子和评论都**最多带 3 张图**（可只发图）
- 个人中心：头像 / 昵称 / 签名（头像可上传图片并裁剪）、**电脑端与手机端各一张自定义背景**
  （可裁剪 + 调透明度）、个人数据总览、修改密码、意见反馈
- 学习工具：进入后**先只列五个功能名**，点哪个才打开哪个——计时器、倒计时（到点响铃）、背单词、离线英汉词典、词汇量测试
- 背单词：粘贴单词表、或上传 PDF / Word / 图片自动提取文字，识别后背诵与考核；
  单词表里没写中文释义的词，导入时自动用内置离线词典补上（自己写了释义的按原样保留）
- 学习记录：按天汇总每天背了多少、考核了多少；点开任意一条进入**独立详情页**看具体背了哪些单词，并可单独下载该条 PDF
- 错词灭错：单词本内「错词」页，把答错过的词练到答对一次即当场消灭
- 词条修正：背诵、考核、灭错、单词列表里发现**释义不对**，点一下就能**直接改成正确的**（立即生效，
  该词历史背诵记录同步更新），并留一条记录供站长核对；离线字典的词改不了，只能报错
- 音标与发音：每个单词自动配美音音标，点 🔊 可听美式发音（离线）
- 词汇量测试：按词频分 20 档抽样，自评 + 释义核对后估算词汇量，结果存云端可看历史
- 排列顺序：导入时可选按「文件顺序」或「字母顺序」保存，单词列表页可随时切换排序
- 分页：单词列表每页 20 / 50 / 100 条，可翻页，也能直接输入页码跳转
- 使用说明：导航栏「说明」页，从三分钟上手到常见问题、逐项讲清各功能怎么用；
  每次访问会弹窗提醒去看一次（一个浏览器会话一次），用户可勾「以后不再提醒」永久关闭
- 策索工作室：页脚入口，**进入需输入密钥**；独立的一页工作室介绍（理念 / 目标 / 成员）
- 界面：明暗切换（浅色 / 深色 / 跟随系统）、**界面样式配色**（默认 / 晚霞 / 大海 / 森林 / 樱粉）、
  **界面透明度**（调低后卡片半透明，自定义背景透出来）、移动端底部导航、桌面宽屏布局
- 离线可用：装过一次之后**断网也能打开页面**；并且有**离线模式**——打卡、任务、背单词、词汇量测试
  都能离线操作，改动先存本机、联网后自动补传；可「添加到主屏幕」当 App 用

## 技术栈

- 前端：原生 HTML / CSS / ES Modules，无构建步骤
- 账号：Supabase Auth
- 数据：Supabase Postgres，启用行级安全（RLS），本人可读写、好友可读
- 托管：GitHub Pages（通过 GitHub Actions 发布 `public/`）

## 配置（首次使用）

### 1. 在 Supabase 建项目

1. 到 https://supabase.com 注册并新建一个免费 Project
2. 打开 **SQL Editor**，把 `supabase/schema.sql` 的内容整段粘贴执行

> `schema.sql` 已包含好友、点赞、个人中心、单词本所需的全部表、RLS 策略与 RPC 函数，
> 且可重复执行。**如果项目是以前建的**，把最新的 `schema.sql` 再整段跑一次即可补上这些对象。

### 2. 关闭邮箱确认（必须）

**Authentication → Sign In / Providers → Email** → 关闭 **Confirm email**。

这一步不能跳过：开启时 `signUp` 不会返回会话，注册后无法自动登录（页面会明确提示你回到这里关闭它）。
关闭之后整个站点不再有任何邮件依赖，也不需要配置 SMTP。

### 3. 填写前端配置

**Project Settings → API** 里复制两样东西，填进 `public/js/config.js`：

```js
export const SUPABASE_URL = 'https://xxxxx.supabase.co';
export const SUPABASE_ANON_KEY = 'eyJ...';
```

> `anon key` 设计上就是可以公开的，安全性由数据库的 RLS 策略保证。
> 请务必确认 `schema.sql` 里的 RLS 语句全部执行成功。

ES Modules 需要通过 http 访问，不能直接双击打开 html：


## 部署

推送到 `main` 分支后，GitHub Actions 会自动把 `public/` 发布到 GitHub Pages。

发布前会先跑一次 `scripts/stamp-assets.mjs`，给产物里的 CSS / JS（**包括模块之间的相对 import**，
模块 URL 不会继承父模块的 query，只给入口脚本加版本号是不够的）统一挂上 `?v=提交号`。
这样每次更新后浏览器都会自动取到新文件，不用再手动强制刷新。
脚本只改发布产物，源码依旧是纯 HTML / CSS / JS，**没有构建步骤**；
词典、音标、OCR 这些大体积文件刻意不加版本号，免得每次发版都重新下载。

首次需要手动开启一次：仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。

## 离线可用（PWA）

访问过一次之后，**断网也能打开页面**；再配合下面的「离线模式」，**数据也能离线用**——
打卡、任务、背单词、词汇量测试照常操作，联网后自动补传。

### 页面离线：Service Worker

- `public/sw.js` 是 Service Worker，缓存策略：
  - **跨域请求（Supabase）一律不拦**，直接走网络——缓存接口数据会让页面显示陈旧的打卡与好友数据
  - **页面导航**网络优先，断网才回缓存（联网时总能拿到最新 HTML）
  - **同源静态资源**缓存优先（css / js 都带 `?v=提交号`，地址变了就是新文件，可以放心用缓存）
- **更新不会卡住**：注册地址带上了部署版本号（`js/offline.js` 用自己 `import.meta.url` 里的 `?v=`），
  每次部署都是一个全新的 `sw.js` 地址，浏览器必定重新安装。安装时把 7 个页面连同
  **整个 js 模块图**（顺着静态 `import` 递归，约 30 个小文件）一起预缓存；
  激活时把上一个版本留下的 `?v=` 条目清掉，而词典、音标这些没有版本号的**大文件保留**，免得每次发版重下 6MB。
- **大文件按需缓存**：`vendor/dict`、`vendor/ipa` 以及 pdf.js / tesseract / mammoth 这些
  装的时候不下载，等真正用到时再缓存。所以「字典」和「词汇量测试」要**联网打开过一次**，
  之后才能离线用（没缓存过又断网，页面上会直接说明）。
- 装了 `public/manifest.json`，可以在手机浏览器里「添加到主屏幕」当 App 用
  （图标是 `public/icons/` 下由 `favicon.svg` 渲染出的 192 / 512 PNG）。

> 新增页面时要记得往 `public/sw.js` 的 `PAGES` 里加一项，否则那个页面不会被预缓存。

### 数据离线：离线模式与自动同步

上面那套只保证**页面**能打开，数据仍在 Supabase 里。所以另有一层离线模式（`public/js/net.js`），
让**数据**也能离线用：打卡、任务、背单词、词汇量测试都能照常操作，改动先存在本机，联网后自动补传。

**模式判定**：分两层，不要混

- `mode` 是**你手动选的**（在线 / 离线），存在本机
- 实际是否按离线处理 = `mode === 'offline' || !navigator.onLine || 刚才有请求失败`

所以断网时会**自动**按离线处理，不用先想起来去切模式；网恢复后也会自动补传。

**切换入口**

- 「我的 → ⚙️ 设置 → 离线模式」两个按钮：主动切到离线（比如知道要断网了）
- 全站顶部**横幅**：处于离线模式、断网、或有改动没同步时出现，写明原因与「N 项待同步」，
  按钮是「切回在线并同步」（离线模式）或「重试同步」（网络问题）。这是切回来的主要入口

**读**：各页面的读取结果按用户缓存在 localStorage。在线时每次读都刷新缓存，离线时直接读缓存。
覆盖：今日打卡与任务、统计、打卡历史、单词本列表、单词本内容、学习记录、词汇量测试历史。
没缓存过的内容在离线时会明确提示「本地还没有这部分数据，联网打开一次就能离线看了」，
并且**直接写在列表区**而不是只弹一个转瞬即逝的提示。

**自动预热**：在线打开「工具」页时，会在后台把**还没缓存过的**单词本内容与学习记录也存一份
（已经有缓存的不重复请求）。所以只要在线进过一次工具页，之后断网也能直接打开单词本背诵，
不用先手动点进每个本子。

**写**：离线时的改动先改本地缓存（界面照常更新），再记一条待同步。**能合并的都合并**，
避免重放时产生重复数据：

| 操作 | 队列条目 | 合并规则 |
| --- | --- | --- |
| 打卡 | `checkin` | 同一天只留一条 |
| 离线新建任务 | `task.add` | 之后的勾选 / 删除就地改这一条（删掉后同步时跳过） |
| 改 / 删已有任务 | `task.update` / `task.remove` | 同一个任务只留最后一条 |
| 背诵 / 考核 / 灭错 | `study` | 同一轮把逐词作答并成一条 |
| 词汇量测试 | `vocab` | 每条独立 |

**同步**：切回在线、浏览器 `online` 事件、或在线状态下打开页面时触发，严格按入队顺序重放：

1. 打卡 —— 已打过（唯一约束 23505）视为成功
2. 任务 —— 离线新建的按当天找（必要时先建）打卡记录再插入；目标不存在视为成功
3. 学习会话 —— 先 `start_study_session` 建会话，再逐词 `record_word_review`
   （**熟练度仍然由服务端算**，客户端不自己实现一套）
4. 词汇量测试

某条失败就停下、**整条保留**、横幅显示失败条数，可重试；任何情况下都不静默丢弃。
同步成功后会把统计与历史的本地缓存清掉，下次读到服务端算出的精确值。

**不支持离线**：登录注册、好友与排行榜、新建 / 删除 / 重命名单词本、导入单词、上传头像背景、
修改密码、意见反馈、词条报错与修改词条。离线时这些会给出「离线模式：「XX」需要联网」，而不是 `Failed to fetch`。

> 离线数据只在本机 localStorage，**换设备或清浏览器数据就没了**。冲突按「以服务端为准 +
> 按顺序重放」处理，不做合并；单人使用场景下够用。

## 注意事项

- Supabase 免费版项目闲置约一周会被暂停，需要到控制台手动唤醒
- GitHub Pages 对公开仓库免费；仓库若转为私有，Pages 将不可用
- 好友通过**邮箱精确匹配**添加，因此登录用户能判断某个邮箱是否已注册（这是该方式的固有代价）；
  若在意隐私，可把 `add_friend_by_email` 换成「邀请码」方案
- 好友之间的打卡与任务在数据库层面互相可读（RLS 的 `friends read` 策略），用于动态流与排行榜
- 单词本不受 Supabase「单次最多返回 1000 行」的限制影响：前端已改为分页拉取，
  上千词的单词本也能完整加载（该默认值位于 Dashboard → Integrations → Data API → Settings → Max rows）

### 关于「四则运算」验证

它由纯前端生成与校验，**只能挡住最明显的脚本提交，不是真正的安全边界**——
攻击者绕过前端直接调用 Supabase API 即可跳过。

真正的防护来自数据库的 RLS 策略。四则运算的作用是给正常用户一个低成本、
无需外部依赖的验证步骤。

### 关于「背单词」的单词表识别

在工具页「背单词」里新建单词本时，直接粘贴单词表即可，每行一个单词。
解析完全在前端完成，支持以下常见写法（会自动识别中英顺序）：

```
apple 苹果          英文 + 空格 + 中文
apple,苹果          逗号 / 全角逗号
apple - 苹果        短横线 / 破折号
apple | 苹果        竖线
apple：苹果          中英文冒号
apple<Tab>苹果      Tab 分隔
1. apple 苹果       行首序号（1. / 1、/ (1) 等）
abandon vt. 放弃     词性标记会自动移到释义前
苹果 apple          中文在前也能识别
```

粘贴后实时显示识别数量，可点「预览」核对，也能一键「交换中英」。
表头行（如「单词 释义」）与 `#` 开头的注释行会被跳过，重复单词只保留第一条。

**没写释义的词会自动补上**：单词表里只有英文、没带中文释义的（包括只留了空白格的），
保存 / 追加时会用内置离线词典自动补一条中文释义；**自己写了释义的一律按原样保存，词典不会覆盖上传的内容**
（哪怕只写了「n.」这种残缺内容也照原样留着）。补了多少条会写在「识别到 N 个单词」后面，预览里能直接核对。
词典里也查不到的词保持无释义，不会瞎编；之后可以在单词列表里手动补。
这一步用的是本地词典文件，**不联网**；词典加载失败也只是补不了释义，不会拦住导入。

多列表格被拍平成一行时也能正确处理：像
`inimical 一贯正确的 contemplate 沉思 dreary 枯燥的` 这样一行挤了好几组，
会按「中文后面又跟英文」的边界自动切成多条，不会只识别出第一条。

背诵支持「认识 / 模糊 / 不认识」三档标记；考核支持选择题（看词选义或看义选词）、
拼写题（看义拼词）与填义题（看词写中文意思，自动判分）。每个单词的熟练度、
最近一次结果与答题正确率都会记录到云端。

在「单词」页可以按状态筛选（全部 / 错词 / 未背 / 认识 / 模糊 / 不认识，数字为该状态的数量），
每行右侧显示最近一次的结果；勾选若干单词后点「考核选中」，会**跳到考核设置页**：
「范围」自动切到 **「选中 N」**，题量也默认等于选中的单词数（想少考几题改一下即可），
选好题型后点「开始考核」。在设置页改动「范围」会取消这次选中。
考核还能按状态限定范围，并用「自定义题量」随机抽取指定数量的题目——
上千词的单词本建议一次抽 50~100 题，而不是一次全考完。

考核默认会**计时**：题目上方显示已用时间，结束后在结果里给出总用时。
还可以开 **「每题 10 秒」的限时**（默认**不限时**，选择记在本地）：
开启后每题独立倒计时，最后 3 秒变红，时间到自动按答错落账并显示正确答案。

### 关于「填义」题的自动判分

考核的「填义」题给英文单词、让你写中文意思，**判分完全在前端完成**，靠中文关键词比对：

- 先归一化：去掉词性标记（`vt.`、`n.` 等）、括号注解、标点与空白，并削掉词尾的「的/地/得」。
- 释义按 `；，、|/` 拆成多个义项，命中**任意一个**就算对。
- **参考答案有两个来源**：单词本里写的释义，加上内置离线词典里同一个词的释义。
  自己导入的释义常常只是词典里的一条，把词典里的其它义项也算对，能明显减少误判——
  例如本子里写「放弃」，你答「抛弃」，词典里 `abandon` 的释义同时含这两条，就算对。
- 命中规则由严到宽：完全一致 → 互相包含（答「苹果」对「苹果树」）→ 相似度（公共子序列占比）≥ 80%
  → 长释义只差一个字 → 同字异序（如「变化无常 / 无常变化」）。
- 单字释义（如「是」）只认完全一致，避免「不是」被判成对；「苹果」对「香蕉」这类照样判错。

中文写法多样，自动判分**做不到百分之百准确**。因此自动判错时**不会立刻计分**，
而是给一个 **「我答对了，算对」** 按钮：

- 点了就**改成按答对算**，按钮随即变成 **「点错了，改回算错」**，可以来回点，手滑点错不慌
- 判定留着不落账，**真正的记分发生在点「下一题」时** —— 在「下一题」之前怎么点，
  都不会写进云端，也不会污染熟练度
- 不点它、直接点「下一题」，就按答错落账

这样一次误判（或一次手滑）都不会留在学习记录里。

「消灭错词」页的题型同样支持 `选择 / 拼写 / 填义`，判分与纠正规则一致。

### 关于「排列顺序」与分页

单词的顺序由数据库里的 `words.position` 列保存，因此**导入是什么顺序，之后打开就是什么顺序**。

- **新建 / 追加**时可选「排列方式」：`文件顺序` 保持单词表里的原始顺序，`字母顺序` 按字母重排后保存。预览区显示的就是最终保存的顺序。
- **单词列表页**可以随时在「文件顺序 / 字母顺序」之间切换，选择会记在本地，下次打开还是上次那样。
  这个切换只影响列表显示，不会改动已保存的顺序，也不影响背诵（背诵有独立的「随机顺序」勾选）。
- 追加的单词总是接在本子末尾，不会插进中间。
- 列表**分页显示**，每页可选 `20 / 50 / 100` 条（默认 50，选择会记住）。上千词的单词本也能一页一页翻到最后一个，
  而不是只渲染前一部分。翻页、筛选、排序三者互不影响，筛选与排序会自动回到第 1 页。
- 列表下方的 **「跳至 __ 页」** 可以直接输入页码：**停顿一下或按回车就跳过去**，
  不用点按钮；输入超出范围的数字会自动夹到合法页码（例如只有 5 页时输入 99 会跳到第 5 页）。
- 「全选本页」只选中**当前这一页显示的单词**（每页 50 条就选 50 个），不会跨页选中整个筛选结果；
  想考更多单词可以用「考核」里的范围 + 自定义题量。

> 这一版给 `words` 表加了 `position` 列，并给旧数据补了编号。
> **必须把最新的 `supabase/schema.sql` 整段再执行一次**，否则顺序不会生效（并且会提示列不存在）。
> 旧单词本在数据库里从未存过文件顺序，无法还原，补编号只是让它们拥有一个稳定、可继续追加的顺序。

### 关于「已掌握」与「学习记录」

**已掌握**看的是熟练度：熟练度最高累计到 5，**达到 2 即计入「已掌握」**。加多少分取决于从哪条路进来：

- **背诵**：点「认识」是**自评**，熟练度 +1，所以要**连对 2 次**才算掌握；`模糊`保持不变。
- **考核**（含「消灭错词」）：这是**真正的检验**，答对一次熟练度 **+2**，也就是**答对一次即掌握**。

答错（含考核答错）一律把熟练度清零。

> 早期版本两条路都只 +1，配上 2 次的掌握线，结果**考核全对一轮熟练度也只有 1，统计上「已掌握」永远是 0**。
> 所以现在考核单独给 +2。熟练度由服务端 `record_word_review` 算（它按会话的 `mode` 判断是不是考核），
> 前端的 `MASTERY_TARGET` 必须和它保持一致。
>
> 这一版改了 `record_word_review`。**升级时要把最新的 `supabase/schema.sql` 整段再执行一次**，
> 否则考核答对仍然只 +1，「已掌握」还是上不去 —— 而且前端会先按 +2 显示、再被服务端返回值改回 1，看着像闪一下。
> 以前答对过的记录**不会**追溯改写（无法还原当时是背诵还是考核、后来又答错过没有），重新考一次就按新规则计入。

**学习记录**在单词本列表右上角点「📅 学习记录」进入：

- 顶部是今日概览：今天背了多少个、考核了多少题、正确率多少
- 下方按天分组，每天一行汇总；每次背诵 / 考核各是一条记录，显示单词本、数量和结果分布
- 点任意一条记录会**跳到独立页面**（`record.html`）看**具体背了哪些单词**以及每个词的结果；
  该页右上角「📄 下载 PDF」可以**只导出这一条记录**，同样走浏览器打印（目标选「另存为 PDF」）
- 可用「全部 / 背诵 / 考核」筛选；列表右上角的「📄 导出 PDF」导出的仍是**当前筛选下的全部记录**

一轮背诵或考核只在**第一次作答时**才会创建记录，翻了两下就退出不会留下空记录。
明细里的单词与释义做了冗余存储，之后删掉单词或整个单词本，历史记录依然完整可读。

> 记录依赖 `supabase/schema.sql` 里的 `study_sessions`、`study_logs` 两张表与两个 RPC
> （`start_study_session`、`record_word_review`）。**升级到这一版必须把最新的 `schema.sql`
> 整段再执行一次**，否则背诵时会报函数不存在的错误。

### 关于「错词灭错」

单词本详情多了一个「错词」页，专门收拢**答错过、又还没练熟**的词：

- **错词**的定义是 `wrong_count > 0`（答错过）**且**熟练度还没到「已掌握」。
- 页面顶部显示「待消灭 / 已消灭 / 累计答错」，点「开始消灭错词」开始，题型可选 `选择` 或 `拼写`。
- 消灭规则直接复用「已掌握」，而灭错按**考核**记分（答对 +2），所以**答对一次就当场消灭**、从池子里消失；
  答错熟练度清零，该词排到队尾继续练，直到整轮练完。中途可点「结束本轮」随时收手，
  收尾会给出本轮消灭数，还有可练的词就给「继续消灭」。
- 判定完全基于现有的熟练度字段，**不需要新增任何列**，旧单词本升级后直接可用。
- 灭错按「考核」写入学习记录（每答一次记一条明细），因此也会出现在「学习记录」里。
- 单词列表页的筛选也有「错词 N」：这里列出**所有答错过的词，包含已经消灭的**
  （已消灭的会多一个「已消灭」标记）。所以消灭之后依然看得到自己曾错在哪儿，不会凭空消失。

> 出题需要单词有释义：缺释义的错词会被跳过，提示里会写明数量。
> 选择题需要本子里至少有 4 个带释义的单词，不足时请改用「拼写」。

### 关于「学习自动记任务」

一轮**背诵 / 考核 / 消灭错词**结束时，会自动往当天的任务里加一条**已完成**的任务，例如
`📖 背单词：SAT（30 个）`、`📝 考核：SAT（20 题 · 正确率 80%）`、`🎯 消灭错词：SAT（消灭 5 个）`。

- 目的就是让「完成任务 / 完成率」能反映学习量，而不是背了一天还是 0%。
- **当天没打卡就会跳过**（任务必须挂在某天的打卡记录下），不报错，也不影响学习记录。
- 每完成一轮记一条，所以同一天背三轮就有三条；更细的明细仍以「学习记录」为准。

### 关于「学习满 5 个词自动打卡」

当天**累计**复习到 **5 个不同单词**就自动补一条当天打卡，不用再手动点。计数口径是 `study_logs`
里当天的**去重单词数**——背诵、考核、消灭错词都算，答对答错都算，所以「不管是考核还是背诵」都生效。
计数与建打卡由服务端 `auto_checkin_if_learned` 一次完成、靠唯一约束天然幂等：

- 已手动打过卡：直接跳过，不会重复建。
- 不足 5 个词：不打卡，也不记学习任务（和原来一致）；满 5 个后自动打卡，并把这一轮学习记入今日任务。
- 打卡内容形如 `📚 学习打卡：今日已学习 N 个单词`，因此会出现在好友动态流里。
- 阈值是 `public/js/config.js` 里的 `AUTO_CHECKIN_WORDS`（默认 5），服务端函数的默认值与之对应，改时一起改。
- 离线时**学习不会即时打卡**，等这轮学习同步到云端后由同步逻辑补上。

> 这一版新增了 `auto_checkin_if_learned` 函数。**升级时要把最新的 `supabase/schema.sql` 整段再执行一次**，
> 否则学满 5 个词也不会自动打卡。

### 关于「界面样式」与「界面透明度」

「我的 → ⚙️ 设置」里新增了两项外观设置（都记在本地，换设备不会跟着走）：

- **界面样式**：默认 / 晚霞 / 大海 / 森林 / 樱粉。只换主色与渐变，浅色与深色**各有一套**，
  所以换配色的同时仍然保留明暗偏好。想再加配色，改 `js/config.js` 里的 `ACCENTS`，
  再到 `css/style.css` 里补一组 `[data-accent="…"]`（深色用 `[data-theme="dark"][data-accent="…"]`）即可。
- **界面透明度**：控制**面板本身**的浓淡（30%~100%）。调低后卡片变半透明，
  上传的自定义背景就透出来了；**文字始终是实心的**，不会跟着一起变淡。
  实现上把 `--bg` / `--surface` / `--surface-soft` 写成了 `rgb(r g b / var(--ui-alpha))`，
  所以改一个变量就能让全站的卡片、顶栏、底部导航一起变透。

> 别和「自定义背景 → 背景透明度」搞混：那个调的是**背景图片本身**的浓淡，
> 这个调的是**界面面板**的浓淡，两个可以叠加使用。
>
> 这两项和主题一样，是在各页面 `<head>` 的内联脚本里**提前套用**的（避免刷新时闪一下），
> 所以 `config.js` 里的 `ACCENT_KEY`、`UI_ALPHA_KEY` 必须与内联脚本里的字符串保持一致。

### 关于「自定义头像与背景」

「我的 → 🎨 外观」里可以：

- **头像图片**：上传后会**先弹裁剪框**（拖动图片调位置、用滑块或滚轮缩放，带三分线辅助），
  确定后按 1:1 裁成 320px 的 JPEG；上传的图片会盖过上面选的 emoji。
- **电脑端 / 手机端背景**：两张分开传，宽屏用横图（16:9，输出 1600px 宽），
  窄屏用竖图（9:16，输出 900px 宽）。手机端不传就**沿用电脑端那张**（反之亦然）。
  选哪张按 `(max-width: 720px)` 判断，窗口跨过断点或手机横竖屏切换时会自动换。
- **背景透明度**：0~100% 的滑块，拖动时即时预览、松手才写库，调低一点正文看着更清楚。

> 为什么背景要两张：背景用 `background-size: cover` 铺满（不变形、不露黑边），
> 但这也意味着会裁。16:9 的横图放到竖屏手机上只能看到中间约 1/4 宽的一条，
> 主体在边上的话就被裁掉了，所以窄屏单独给一张竖图效果最好。

图片存在 Supabase Storage 的 **`media` 公开桶**里，路径固定为 `<用户id>/avatar.jpg`、
`<用户id>/background.jpg` 与 `<用户id>/background-mobile.jpg`；覆盖上传后会带一个时间戳参数，
免得浏览器与 CDN 继续用旧图。「公开」只影响读取（知道链接就能看，头像本来也要给好友看），
写入 / 覆盖 / 删除都只允许操作自己目录下的文件。

> 这一版给 `profiles` 加了 `avatar_url` / `background_url` / `background_mobile_url` /
> `background_opacity` 四列，并新增 `media` 存储桶及其读写策略。
> **升级时要把最新的 `supabase/schema.sql` 整段再执行一次**，否则上传会失败（提示桶或列不存在）。

### 关于「词条修正 / 报错」

释义有两个来源——**导入时从单词表里切出来的原文**，以及**内置离线词典**（导入时没带释义的词会先用词典补上，
带了释义的以单词表里的原文为准）。中英切分并不总是可靠，
像 `florid: flowery; elaborate; overwrought (style of writing)` 这种一行挤了好几个同义词、
还带半截括号的条目，就可能被切成「单词」是一长串英文、「释义」只剩 `贬义)` 这样的碎片。

凡是展示释义的地方都能**直接改成正确的**（离线字典除外，那里只能报错）：

- **背诵**：翻开释义后，卡片下方出现「✏️ 释义不对？点这里改」
- **考核 / 消灭错词**：每答完一题，反馈区里有一个小号入口
- **单词列表**：每行右侧的「修正」（与「删除」一样，桌面端 hover 才显形，触摸设备常驻）
- **离线字典**：查词结果里「＋ 加入生词本」旁边的「⚠️ 报错」——内置词典是随包发行的静态文件，
  单个用户改不了它，所以那里保持只报错

点开后弹窗里预填好**当前的单词与释义**（免得改到别的词上），两个字段都能编辑：

- **保存修改** → 立即写回你自己的词条，背诵卡片、考核题目、单词列表马上生效；该词**历史背诵
  记录里的单词与释义也会一起更新**，记录页不会新旧对不上。
- 「单词」留空会被拦下；单词和释义都没动就等于「没有改动」，不写库。
- 顺带选一个原因（可不选）或补一句说明，会连同改后的内容一起记进 `word_reports` 表，
  站长在 Supabase 后台的 **Table Editor → word_reports** 里能看到谁改了什么。

- 修改只动**文本**：不碰熟练度、不改历史对错判定，已经答过的那一题也不回溯改判。
- 记录里带上了单词 id、单词本 id、改后的单词与释义、出处（背诵 / 考核 / 灭错 / 列表 / 字典）与原因，
  所以即使之后把词删了，记录内容依然看得懂。
- 每条只有本人能读写（RLS 策略），和意见反馈一样。
- 修正与报错都**需要联网**（和意见反馈同样处理），离线时点了会提示「离线模式：「修改词条」需要联网」，
  不会静默丢掉。
- 服务端由 `update_word` 一次事务完成「改词条 + 同步历史明细」，不会出现「词条改了、历史没改」
  这种半截状态。

> 这一版新增了 `word_reports` 表与 `update_word` 函数。**升级时要把最新的 `supabase/schema.sql`
> 整段再执行一次**，否则提交报错会提示表不存在、保存修改会提示函数不存在。

### 关于「离线字典」

工具页的「🔤 字典」是一个**完全离线**的英汉查询：输入英文单词，下面立刻显示
**美音音标 + 中文释义**，点音标旁的 🔊 可以朗读（朗读用的是浏览器自带的语音合成，见下一节）。

数据来自两份内置词库，都只在**第一次打开字典页时加载一次**，之后不再联网：

| 内容 | 数据文件 | 规模 |
| --- | --- | --- |
| 音标 | `public/vendor/ipa/en_US.txt` | 125,927 条，约 2.9MB |
| 中文释义 | `public/vendor/dict/en_zh.txt` | 59,137 条，约 3MB |

- 中文词库取自 [ECDICT](https://github.com/skywind3000/ECDICT)（**MIT License**），只保留**常用词**：
  有语料库词频排名、或有考试大纲标签（中高考 / 四六级 / 考研 / 雅思 / 托福 / GRE）、
  或是柯林斯星级 / 牛津核心词。裁剪细节见 `public/vendor/dict/README.md`。
- 输入即查，不需要点按钮；也会自动去掉括号、词性等修饰再查一次。
- 同时命中音标与释义就都显示；只命中音标会说明「不在中文词库范围内」；
  两者都没有会提示「没有收录」。生僻词、地名、人名大多不在收录范围内。
- 在输入框里按回车可以直接朗读当前单词。
- 查到的词可以点 **「＋ 加入生词本」** 直接收进单词本：会弹窗让你挑一本（**每次都问**，不用先想好加到哪）。
  释义会压成一行存进去。**同一个词不会重复添加**，已经在里面时会直接提示。
  离线时也能加——先记在本机，联网后自动补传（顶部横幅会显示待同步条数）。

### 关于「词汇量测试」

工具页的「📊 词汇量测试」用来估一下现在大概认识多少词，逻辑在 `public/js/vocab.js`。

- **题库**：`public/vendor/dict/freq.txt`，约 2.6 万词。由
  [FrequencyWords](https://github.com/hermitdave/FrequencyWords) 的 5 万词表与内置词典**取交集**而来，
  按词频重新连续编号；释义直接查内置词典。裁剪规则见 `public/vendor/dict/README.md`。
- **流程**：按词频切成 20 个频段，每档随机抽同样多的词 → 先**只看单词**判断认不认识
  （这一步**不给释义**，给了就等于送答案）→ 答完把勾了「认识」的词**连同释义再列一遍**，
  让你取消虚报的 → 出结果。
- **估算**：`Σ(每档词数 × 该档认识比例)`；浮动范围由各档二项分布的方差相加得出（约 95% 置信区间）。
  题量可选 60 / 100 / 140 题，**题量越大范围越窄**。因为是抽样，不要跟别的网站测出的数字精确对齐。
- 估算上限就是词表本身（约 2.6 万词）：全部认识时结果是 26,400，意思是「这份词表基本都认识」。
  生僻词与专有名词不在词表里（词频表已经滤掉人名、地名、缩写）。
- 历史记录存在 `vocab_tests` 表，**只有本人可见**，不参与好友排行榜；可以逐条删除。

> 这一版新增了 `vocab_tests` 表。**升级时要把最新的 `supabase/schema.sql` 整段再执行一次**，
> 否则测试结果会保存失败（页面上会直接提示这句话）。

### 关于音标与美音发音

背诵卡片、单词列表和考核反馈里都会显示音标，点 🔊 即可朗读（美音）。
考核里刻意**作答后**才显示音标，否则拼写题等于直接给答案。

- **音标**取自本地词典 `public/vendor/ipa/en_US.txt`（125,927 条，约 2.9MB），
  打开单词本时后台加载一次，之后完全离线。词典未收录的词（多为生僻词，
  实测约 5%，如 ineluctable、fecund）只是不显示音标，不影响其他功能。
- **发音**用浏览器内置的语音合成（`speechSynthesis`），优先挑美音语音，
  实测会选中 Microsoft Zira / David 或 Google US English，零依赖、零延迟。
  若系统没有英文语音则不会朗读，点 🔊 会给出提示。
- 背诵页可勾选「自动发音」，翻到下一个词时自动朗读。
- 音标数据来自 [ipa-dict](https://github.com/open-dict-data/ipa-dict)（MIT License），
  详见 `public/vendor/ipa/README.md`。

### 关于「背单词」的文件上传

除了粘贴，也可以点「上传文件」，或把文件直接拖到文本框里。
解析全部在本地完成，**文件不会上传到任何服务器**：

| 格式 | 处理方式 | 说明 |
| --- | --- | --- |
| `.pdf` | pdf.js 提取文字层 | 按坐标把「单词 / 释义」两列合并成一行；**扫描版 PDF**（没有文字层）会自动改用 OCR |
| `.docx` | mammoth 解析 | 表格按「单元格 → Tab」还原，最贴合单词表 |
| `.doc` | 先嗅探真实格式 | 实为 docx / RTF 的能正常解析；真正的 Word 97-2003 二进制格式浏览器无法解析，会提示另存为 `.docx` |
| `.jpg` `.png` `.webp` `.bmp` | tesseract.js OCR | 首次使用会加载约 8MB 的识别引擎与中文包，之后走缓存 |
| `.txt` `.rtf` | 直接读取 | RTF 会转成纯文本 |

识别结果会**填进文本框**而不是直接保存，方便你核对、修改后再保存；
文本框里原有的内容不会被覆盖，新内容追加在后面。多个文件可以一次选中。

> **OCR 准确率说明**：用的是 `tessdata_fast` 轻量中文模型，印刷体的英文单词基本无误，
> 中文释义仍可能有个别错字（实测「香蕉」会识成「香基」）。中文部分请务必核对。
> 想提高精度，可把 `public/vendor/tesseract-lang/chi_sim.traineddata` 换成
> [tessdata_best](https://github.com/tesseract-ocr/tessdata_best) 的同名文件（体积约 40MB）。
>
> 另外实测发现中英混合识别（`chi_sim+eng`）反而比单用 `chi_sim` 更容易认错中文，
> 因此这里只用中文模型；它本身包含拉丁字母，英文单词照样能识别。
