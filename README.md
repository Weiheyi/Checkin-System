# 学习打卡系统

一个纯静态的学习打卡网站：每天打卡、记录任务、统计连续天数与完成率。
托管在 **GitHub Pages**，账号与数据由 **Supabase** 提供。

线上地址：https://Weiheyi.github.io/Checkin-System/

## 功能

- 邮箱 + 密码注册登录（不依赖任何邮件流程，注册后直接可用）
- 人机验证：登录、注册均需先通过「四则运算」快速验证
- 每日打卡（每人每天一次，重复打卡会被拦截）
- 任务管理：添加、勾选完成 / 取消、删除；**背完 / 考完一轮会按已完成为你自动记一条任务**
- 学习统计：连续天数、打卡天数、完成任务数、完成率
- 打卡历史：最近记录与完成进度
- 好友：邮箱精确添加 / 删除、好友打卡动态流、排行榜 PK、点赞鼓励
- 个人中心：头像 / 昵称 / 签名、个人数据总览、修改密码、意见反馈
- 学习工具：进入后**先只列四个功能名**，点哪个才打开哪个——计时器、倒计时（到点响铃）、背单词、离线英汉词典
- 背单词：粘贴单词表、或上传 PDF / Word / 图片自动提取文字，识别后背诵与考核
- 学习记录：按天汇总每天背了多少、考核了多少，可展开看具体背了哪些单词
- 错词灭错：单词本内「错词」页，把答错过的词反复练到连续答对 2 次即当场消灭
- 音标与发音：每个单词自动配美音音标，点 🔊 可听美式发音（离线）
- 排列顺序：导入时可选按「文件顺序」或「字母顺序」保存，单词列表页可随时切换排序
- 分页：单词列表每页 20 / 50 / 100 条，可翻页，也能直接输入页码跳转
- 使用说明：导航栏「说明」页，从三分钟上手到常见问题、逐项讲清各功能怎么用
- 界面：暗色模式（浅色 / 深色 / 跟随系统）、移动端底部导航

## 技术栈

- 前端：原生 HTML / CSS / ES Modules，无构建步骤
- 账号：Supabase Auth
- 数据：Supabase Postgres，启用行级安全（RLS），本人可读写、好友可读
- 托管：GitHub Pages（通过 GitHub Actions 发布 `public/`）

## 配置（首次使用）

### 1. 在 Supabase 建项目

1. 到 https://supabase.com 注册并新建一个免费 Project
2. 打开 **SQL Editor**，把 `supabase/schema.sql` 的内容整段粘贴执行

> `schema.sql` 已包含好友、点赞、个人中心、单词本所需的全部表、RLS 策略与 RPC 函数，
> 且可重复执行。**如果项目是以前建的**，把最新的 `schema.sql` 再整段跑一次即可补上这些对象。

### 2. 关闭邮箱确认（必须）

**Authentication → Sign In / Providers → Email** → 关闭 **Confirm email**。

这一步不能跳过：开启时 `signUp` 不会返回会话，注册后无法自动登录（页面会明确提示你回到这里关闭它）。
关闭之后整个站点不再有任何邮件依赖，也不需要配置 SMTP。

### 3. 填写前端配置

**Project Settings → API** 里复制两样东西，填进 `public/js/config.js`：

```js
export const SUPABASE_URL = 'https://xxxxx.supabase.co';
export const SUPABASE_ANON_KEY = 'eyJ...';
```

> `anon key` 设计上就是可以公开的，安全性由数据库的 RLS 策略保证。
> 请务必确认 `schema.sql` 里的 RLS 语句全部执行成功。

## 本地预览

ES Modules 需要通过 http 访问，不能直接双击打开 html：

```
npx serve public
```

然后打开提示的地址（默认 http://localhost:3000）。

## 部署

推送到 `main` 分支后，GitHub Actions 会自动把 `public/` 发布到 GitHub Pages。

发布前会先跑一次 `scripts/stamp-assets.mjs`，给产物里的 CSS / JS（**包括模块之间的相对 import**，
模块 URL 不会继承父模块的 query，只给入口脚本加版本号是不够的）统一挂上 `?v=提交号`。
这样每次更新后浏览器都会自动取到新文件，不用再手动强制刷新。
脚本只改发布产物，源码依旧是纯 HTML / CSS / JS，**没有构建步骤**；
词典、音标、OCR 这些大体积文件刻意不加版本号，免得每次发版都重新下载。

首次需要手动开启一次：仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。

## 注意事项

- Supabase 免费版项目闲置约一周会被暂停，需要到控制台手动唤醒
- GitHub Pages 对公开仓库免费；仓库若转为私有，Pages 将不可用
- 好友通过**邮箱精确匹配**添加，因此登录用户能判断某个邮箱是否已注册（这是该方式的固有代价）；
  若在意隐私，可把 `add_friend_by_email` 换成「邀请码」方案
- 好友之间的打卡与任务在数据库层面互相可读（RLS 的 `friends read` 策略），用于动态流与排行榜
- 单词本不受 Supabase「单次最多返回 1000 行」的限制影响：前端已改为分页拉取，
  上千词的单词本也能完整加载（该默认值位于 Dashboard → Integrations → Data API → Settings → Max rows）

### 关于「四则运算」验证

它由纯前端生成与校验，**只能挡住最明显的脚本提交，不是真正的安全边界**——
攻击者绕过前端直接调用 Supabase API 即可跳过。

真正的防护来自数据库的 RLS 策略。四则运算的作用是给正常用户一个低成本、
无需外部依赖的验证步骤。

### 关于「背单词」的单词表识别

在工具页「背单词」里新建单词本时，直接粘贴单词表即可，每行一个单词。
解析完全在前端完成，支持以下常见写法（会自动识别中英顺序）：

```
apple 苹果          英文 + 空格 + 中文
apple,苹果          逗号 / 全角逗号
apple - 苹果        短横线 / 破折号
apple | 苹果        竖线
apple：苹果          中英文冒号
apple<Tab>苹果      Tab 分隔
1. apple 苹果       行首序号（1. / 1、/ (1) 等）
abandon vt. 放弃     词性标记会自动移到释义前
苹果 apple          中文在前也能识别
```

粘贴后实时显示识别数量，可点「预览」核对，也能一键「交换中英」。
表头行（如「单词 释义」）与 `#` 开头的注释行会被跳过，重复单词只保留第一条。

多列表格被拍平成一行时也能正确处理：像
`inimical 一贯正确的 contemplate 沉思 dreary 枯燥的` 这样一行挤了好几组，
会按「中文后面又跟英文」的边界自动切成多条，不会只识别出第一条。

背诵支持「认识 / 模糊 / 不认识」三档标记；考核支持选择题（看词选义或看义选词）、
拼写题（看义拼词）与填义题（看词写中文意思，自动判分）。每个单词的熟练度、
最近一次结果与答题正确率都会记录到云端。

在「单词」页可以按状态筛选（全部 / 错词 / 未背 / 认识 / 模糊 / 不认识，数字为该状态的数量），
每行右侧显示最近一次的结果；勾选若干单词后点「考核选中」，会**跳到考核设置页**：
「范围」自动切到 **「选中 N」**，题量也默认等于选中的单词数（想少考几题改一下即可），
选好题型后点「开始考核」。在设置页改动「范围」会取消这次选中。
考核还能按状态限定范围，并用「自定义题量」随机抽取指定数量的题目——
上千词的单词本建议一次抽 50~100 题，而不是一次全考完。

考核默认会**计时**：题目上方显示已用时间，结束后在结果里给出总用时。
还可以开 **「每题 10 秒」的限时**（默认**不限时**，选择记在本地）：
开启后每题独立倒计时，最后 3 秒变红，时间到自动按答错落账并显示正确答案。

### 关于「填义」题的自动判分

考核的「填义」题给英文单词、让你写中文意思，**判分完全在前端完成**，靠中文关键词比对：

- 先归一化：去掉词性标记（`vt.`、`n.` 等）、括号注解、标点与空白，并削掉词尾的「的/地/得」。
- 释义按 `；，、|/` 拆成多个义项，命中**任意一个**就算对。
- **参考答案有两个来源**：单词本里写的释义，加上内置离线词典里同一个词的释义。
  自己导入的释义常常只是词典里的一条，把词典里的其它义项也算对，能明显减少误判——
  例如本子里写「放弃」，你答「抛弃」，词典里 `abandon` 的释义同时含这两条，就算对。
- 命中规则由严到宽：完全一致 → 互相包含（答「苹果」对「苹果树」）→ 相似度（公共子序列占比）≥ 80%
  → 长释义只差一个字 → 同字异序（如「变化无常 / 无常变化」）。
- 单字释义（如「是」）只认完全一致，避免「不是」被判成对；「苹果」对「香蕉」这类照样判错。

中文写法多样，自动判分**做不到百分之百准确**。因此自动判错时**不会立刻计分**，
而是给一个 **「我答对了，算对」** 按钮：点了就按答对重新计分；不点、直接点「下一题」才按错落账。
这样一次误判不会污染熟练度。

「消灭错词」页的题型同样支持 `选择 / 拼写 / 填义`，判分与纠正规则一致。

### 关于「排列顺序」与分页

单词的顺序由数据库里的 `words.position` 列保存，因此**导入是什么顺序，之后打开就是什么顺序**。

- **新建 / 追加**时可选「排列方式」：`文件顺序` 保持单词表里的原始顺序，`字母顺序` 按字母重排后保存。预览区显示的就是最终保存的顺序。
- **单词列表页**可以随时在「文件顺序 / 字母顺序」之间切换，选择会记在本地，下次打开还是上次那样。
  这个切换只影响列表显示，不会改动已保存的顺序，也不影响背诵（背诵有独立的「随机顺序」勾选）。
- 追加的单词总是接在本子末尾，不会插进中间。
- 列表**分页显示**，每页可选 `20 / 50 / 100` 条（默认 50，选择会记住）。上千词的单词本也能一页一页翻到最后一个，
  而不是只渲染前一部分。翻页、筛选、排序三者互不影响，筛选与排序会自动回到第 1 页。
- 列表下方的 **「跳至 __ 页」** 可以直接输入页码：**停顿一下或按回车就跳过去**，
  不用点按钮；输入超出范围的数字会自动夹到合法页码（例如只有 5 页时输入 99 会跳到第 5 页）。
- 「全选本页」只选中**当前这一页显示的单词**（每页 50 条就选 50 个），不会跨页选中整个筛选结果；
  想考更多单词可以用「考核」里的范围 + 自定义题量。

> 这一版给 `words` 表加了 `position` 列，并给旧数据补了编号。
> **必须把最新的 `supabase/schema.sql` 整段再执行一次**，否则顺序不会生效（并且会提示列不存在）。
> 旧单词本在数据库里从未存过文件顺序，无法还原，补编号只是让它们拥有一个稳定、可继续追加的顺序。

### 关于「已掌握」与「学习记录」

**已掌握**的判定是「连续答对 2 次」：`认识`（含考核答对）让熟练度 +1，`不认识`（含答错）
直接清零，`模糊`保持不变。熟练度最高累计到 5，达到 2 即计入「已掌握」。
（早期版本要求连续 3 次，配上上千词的词库几乎永远到不了，所以那个数字长期是 0。）

**学习记录**在单词本列表右上角点「📅 学习记录」进入：

- 顶部是今日概览：今天背了多少个、考核了多少题、正确率多少
- 下方按天分组，每天一行汇总；每次背诵 / 考核各是一条记录，显示单词本、数量和结果分布
- 点任意一条记录即可展开，看到**具体背了哪些单词**以及每个词的结果
- 可用「全部 / 背诵 / 考核」筛选

一轮背诵或考核只在**第一次作答时**才会创建记录，翻了两下就退出不会留下空记录。
明细里的单词与释义做了冗余存储，之后删掉单词或整个单词本，历史记录依然完整可读。

> 记录依赖 `supabase/schema.sql` 里的 `study_sessions`、`study_logs` 两张表与两个 RPC
> （`start_study_session`、`record_word_review`）。**升级到这一版必须把最新的 `schema.sql`
> 整段再执行一次**，否则背诵时会报函数不存在的错误。

### 关于「错词灭错」

单词本详情多了一个「错词」页，专门收拢**答错过、又还没练熟**的词：

- **错词**的定义是 `wrong_count > 0`（答错过）**且**熟练度还没到「已掌握」（连续答对 2 次）。
- 页面顶部显示「待消灭 / 已消灭 / 累计答错」，点「开始消灭错词」开始，题型可选 `选择` 或 `拼写`。
- 消灭规则直接复用「已掌握」：答对一次熟练度 +1，**达标即当场消灭**、从池子里消失；
  答错熟练度清零，该词排到队尾继续练，直到整轮练完。中途可点「结束本轮」随时收手，
  收尾会给出本轮消灭数，还有可练的词就给「继续消灭」。
- 判定完全基于现有的熟练度字段，**不需要改动数据库**，旧单词本升级后直接可用。
- 灭错按「考核」写入学习记录（每答一次记一条明细），因此也会出现在「学习记录」里。
- 单词列表页的筛选也有「错词 N」：这里列出**所有答错过的词，包含已经消灭的**
  （已消灭的会多一个「已消灭」标记）。所以消灭之后依然看得到自己曾错在哪儿，不会凭空消失。

> 出题需要单词有释义：缺释义的错词会被跳过，提示里会写明数量。
> 选择题需要本子里至少有 4 个带释义的单词，不足时请改用「拼写」。

### 关于「学习自动记任务」

一轮**背诵 / 考核 / 消灭错词**结束时，会自动往当天的任务里加一条**已完成**的任务，例如
`📖 背单词：SAT（30 个）`、`📝 考核：SAT（20 题 · 正确率 80%）`、`🎯 消灭错词：SAT（消灭 5 个）`。

- 目的就是让「完成任务 / 完成率」能反映学习量，而不是背了一天还是 0%。
- **当天没打卡就会跳过**（任务必须挂在某天的打卡记录下），不报错，也不影响学习记录。
- 每完成一轮记一条，所以同一天背三轮就有三条；更细的明细仍以「学习记录」为准。

### 关于「意见反馈」

「我的」页有 **💬 意见反馈**：写下内容（可留联系方式）提交，下面是**你自己提交过的历史反馈**，
可以随时删除。反馈存在数据库的 `feedback` 表里，每条只有本人能读写（RLS 策略），
站长在 Supabase 后台的 **Table Editor → feedback** 里就能看到全部。

> 这一版新增了 `feedback` 表。**升级时要把最新的 `supabase/schema.sql` 整段再执行一次**，
> 否则提交反馈会提示表不存在。

### 关于「离线字典」

工具页的「🔤 字典」是一个**完全离线**的英汉查询：输入英文单词，下面立刻显示
**美音音标 + 中文释义**，点音标旁的 🔊 可以朗读（朗读用的是浏览器自带的语音合成，见下一节）。

数据来自两份内置词库，都只在**第一次打开字典页时加载一次**，之后不再联网：

| 内容 | 数据文件 | 规模 |
| --- | --- | --- |
| 音标 | `public/vendor/ipa/en_US.txt` | 125,927 条，约 2.9MB |
| 中文释义 | `public/vendor/dict/en_zh.txt` | 59,137 条，约 3MB |

- 中文词库取自 [ECDICT](https://github.com/skywind3000/ECDICT)（**MIT License**），只保留**常用词**：
  有语料库词频排名、或有考试大纲标签（中高考 / 四六级 / 考研 / 雅思 / 托福 / GRE）、
  或是柯林斯星级 / 牛津核心词。裁剪细节见 `public/vendor/dict/README.md`。
- 输入即查，不需要点按钮；也会自动去掉括号、词性等修饰再查一次。
- 同时命中音标与释义就都显示；只命中音标会说明「不在中文词库范围内」；
  两者都没有会提示「没有收录」。生僻词、地名、人名大多不在收录范围内。
- 在输入框里按回车可以直接朗读当前单词。

### 关于音标与美音发音

背诵卡片、单词列表和考核反馈里都会显示音标，点 🔊 即可朗读（美音）。
考核里刻意**作答后**才显示音标，否则拼写题等于直接给答案。

- **音标**取自本地词典 `public/vendor/ipa/en_US.txt`（125,927 条，约 2.9MB），
  打开单词本时后台加载一次，之后完全离线。词典未收录的词（多为生僻词，
  实测约 5%，如 ineluctable、fecund）只是不显示音标，不影响其他功能。
- **发音**用浏览器内置的语音合成（`speechSynthesis`），优先挑美音语音，
  实测会选中 Microsoft Zira / David 或 Google US English，零依赖、零延迟。
  若系统没有英文语音则不会朗读，点 🔊 会给出提示。
- 背诵页可勾选「自动发音」，翻到下一个词时自动朗读。
- 音标数据来自 [ipa-dict](https://github.com/open-dict-data/ipa-dict)（MIT License），
  详见 `public/vendor/ipa/README.md`。

### 关于「背单词」的文件上传

除了粘贴，也可以点「上传文件」，或把文件直接拖到文本框里。
解析全部在本地完成，**文件不会上传到任何服务器**：

| 格式 | 处理方式 | 说明 |
| --- | --- | --- |
| `.pdf` | pdf.js 提取文字层 | 按坐标把「单词 / 释义」两列合并成一行；**扫描版 PDF**（没有文字层）会自动改用 OCR |
| `.docx` | mammoth 解析 | 表格按「单元格 → Tab」还原，最贴合单词表 |
| `.doc` | 先嗅探真实格式 | 实为 docx / RTF 的能正常解析；真正的 Word 97-2003 二进制格式浏览器无法解析，会提示另存为 `.docx` |
| `.jpg` `.png` `.webp` `.bmp` | tesseract.js OCR | 首次使用会加载约 8MB 的识别引擎与中文包，之后走缓存 |
| `.txt` `.rtf` | 直接读取 | RTF 会转成纯文本 |

识别结果会**填进文本框**而不是直接保存，方便你核对、修改后再保存；
文本框里原有的内容不会被覆盖，新内容追加在后面。多个文件可以一次选中。

> **OCR 准确率说明**：用的是 `tessdata_fast` 轻量中文模型，印刷体的英文单词基本无误，
> 中文释义仍可能有个别错字（实测「香蕉」会识成「香基」）。中文部分请务必核对。
> 想提高精度，可把 `public/vendor/tesseract-lang/chi_sim.traineddata` 换成
> [tessdata_best](https://github.com/tesseract-ocr/tessdata_best) 的同名文件（体积约 40MB）。
>
> 另外实测发现中英混合识别（`chi_sim+eng`）反而比单用 `chi_sim` 更容易认错中文，
> 因此这里只用中文模型；它本身包含拉丁字母，英文单词照样能识别。
